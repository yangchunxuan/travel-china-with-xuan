# Route Reality v2 handoff

Status: **INTERNAL HANDOFF READY — DO NOT IMPLEMENT OR PUBLISH**

## 1. Decision for central review

The seven-field model now has a mechanically reviewable contract. The previous
semantic, topology, invalid-result and unknown-range blockers have written
dispositions. The correct next action is a central contract review, followed by
a separate numerical policy decision. It is not public implementation.

No executable code, API, component, registry entry, sitemap entry, metadata,
schema markup, index URL, analytics event or commercial pathway should be
created from this package.

## 2. What is ready

- strict exact-object validation model;
- stable meanings for all seven inputs;
- relational and event-topology rules;
- correlated unknown-state semantics;
- joint day-classification reconciliation;
- gross/applied/net accounting identities;
- discriminated output union and closed codes;
- unknown-alert basis and deterministic serialization rules;
- all-unknown non-actionable handling;
- privacy/network/storage/indexing prohibitions; and
- a 41-scenario internal contract matrix, including open-jaw/return-gateway,
  fixed-booking-conflict and fatigue-chain handoff cases that the seven inputs
  deliberately do not calculate.

## 3. What remains unapproved

The package deliberately contains no approved values for:

- time-window usable-hour bands;
- interior-day capacity;
- cross-city, interchange or hotel-change burdens;
- pace multipliers or ranges;
- equivalent-day divisor;
- full/fragment thresholds;
- alert ratios or severity thresholds;
- buffer arithmetic or rounding; or
- confidence scoring.

Central must review these as one immutable policy pack, not approve isolated
numbers. The old draft is not a default pack.

## 4. Required later implementation sequence

Only after a new authorization:

1. Freeze `PolicyPack` values and a `policyPackVersion` with editorial rationale;
   bump the schema/model-contract version and replace the internal draft's
   required `policyPackVersion:null` with that exact approved identifier.
2. Add golden outputs to every numeric-capable fixture without changing the
   structural expectations in this package.
3. Build an exhaustive bounded oracle for small/all concrete domains.
4. Build the optimized pure evaluator and prove equivalence to the oracle.
5. Validate outputs against `data-model.schema.json` plus relational assertions
   that JSON Schema alone cannot express.
6. Add property tests for day reconciliation, unknown containment,
   monotonicity, non-negative values and determinism.
7. Run a network-denial harness and assert zero calls.
8. Run storage/log/analytics/URL-state static and runtime traps and assert zero
   payload copies.
9. Snapshot every output field and assert no route, place, transport, personal
   data or service-recommendation fields.
10. Add localized EN/ZH/KO presentation dictionaries outside the core and test
    code-to-copy parity.
11. Repeat privacy, security, accessibility, search and product reviews.
12. Seek explicit central authorization for any surface. Absence of a rejection
    is not authorization.

## 5. Acceptance matrix for a later engine

| Area | Minimum evidence |
|---|---|
| Schema | Exact seven keys; wrong types, missing/extra keys and enum variants rejected in stable order. |
| Relations | `C + H <= N - 1` and `T <= N + 1` enforced for known and unknown states. |
| Unknowns | Correlated feasible enumeration; no impossible endpoint mixtures; known-result containment. |
| Topology | One accommodation event per transition day; one complex interchange per calendar day; no unlimited stacking. |
| Classification | Every concrete tuple reconciles `F + G + U = calendarDays`; marginals labelled non-additive. |
| Accounting | Gross ≥ applied ≥ 0; applied ≤ baseline; net = baseline − applied; no negative zero. |
| Invalid arm | `result:null`, ordered errors, no score and no alerts. |
| Alert basis | All-witness confirmed; some-witness possible; possible-only never rendered confirmed. |
| All unknown | Insufficient input, low confidence, decision not useful, null/non-actionable buffer. |
| Determinism | Byte-equivalent canonical output for repeats and deep clones. |
| Network | Network primitives disabled; zero attempted calls. |
| Data minimization | Only seven scalar values; no personal/free-text/exact-transport fields or inference. |
| Persistence | Zero input/output logging, analytics, storage, session or URL serialization. |
| Public surface | No app/API/public/registry/sitemap/metadata/schema import or generated combination. |

## 6. Fixture execution rules

`internal-examples.json` contains JSON-native inputs and two
`javascript-expression` fixtures for values JSON cannot encode. A future
harness must never use `eval` on fixture text in product code. Its isolated test
adapter may construct those values explicitly by fixture ID.

Fixtures without numeric expected values are not incomplete: they intentionally
prevent the unapproved old coefficients from becoming de facto policy. Once a
policy pack is approved, add golden numeric expectations under a named
`policyPackVersion`; do not overwrite the contract-only expectations, and do
not reuse `route-reality-v2.0.0-internal-draft` for an executable engine.

## 7. Handoff boundaries for editorial and commercial teams

- Public planning education continues to route to
  `is-your-china-itinerary-too-rushed`.
- Route Reality does not create a new canonical page or keyword owner.
- It does not generate an itinerary, remove cities, select transport or certify
  feasibility.
- It does not recommend, preselect or qualify anyone for Route Review, Route
  Build or ground-support services.
- Any later human-help link must be reviewed outside the calculation result and
  must not be triggered by an alert or pace value.

## 8. Stop conditions

Stop and return to central review if any proposal:

- adds an eighth input or free text;
- changes `crossCityMoves` to legs or includes day trips;
- makes `hotelChanges` overlap counted cross-city changes;
- mixes independent unknown endpoints;
- omits joint classifications;
- subtracts gross burden directly from baseline;
- stacks unlimited events on one day;
- renders a possible extreme as confirmed;
- returns an executable buffer with unknown nights;
- logs or serializes input state;
- calls live transport or other networks;
- creates URLs or pages from input combinations; or
- connects a result to a service recommendation.

IMPLEMENTATION AUTHORIZATION PENDING**.
