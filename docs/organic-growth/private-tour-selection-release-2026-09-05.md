# Private-tour selection release order

Backend release checkpoint on 2026-09-05: `notify-inquiries`, the selection SQL and `v1-inquiries` have been deployed. At this checkpoint, the frontend still awaits [PR #125](https://github.com/yangchunxuan/travel-china-with-xuan/pull/125) merge and its automatic Pages deployment. No production inquiry, notification receipt or GA ingestion was tested. See the [backend release record](../release-notes/private-tour-selection-backend-release-20260905.md); consult the PR, its deployment and the latest [production release record](../release-notes/README.md) for subsequent frontend status.

The homepage email contract accepts an optional `productInterest.selection` with exactly `packageId` and numeric `travelers` (2 or 4). Package IDs are checked against the selected tour. The canonical product name is checked server-side; customer names, prices and free text are rejected. Old email-only and product-identity-only requests retain their existing semantic hash shape. A changed selection changes the semantic hash, so reusing a submission key with a changed selection remains a conflict.

The 2026-09-05 read-only production preflight verified 11 existing RPC signatures and their role privileges, including all three traffic wrappers. The 2026-08-23 release record is historical and does not establish their current absence. The intake uses the original inquiry RPCs whenever there is no usable traffic-session hash, including when the optional hashing secret is unavailable. Only a usable hash selects the existing atomic traffic wrapper. It never retries a failed or ambiguous persistence call through another RPC.
